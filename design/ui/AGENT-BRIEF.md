# Brief for page builders

You are building high-fidelity, responsive page designs (static HTML + CSS) for **Wi-Fight**, a website that checks whether a household gets the internet speed it pays for. These are design mockups, not the working app: no JavaScript frameworks, no build step, no real network calls. Small inline `<script>` is allowed only for trivial visual state.

## Read these first (all paths under `design/`)
1. `04-design-direction.md` : the principles, tokens, and which borrowed pattern lands on which page.
2. `05-sample-data.md` : canonical numbers. Use them exactly. Never invent different values.
3. `01-product-blueprint.md` : screen map, and what AI and security do on each page.
4. `ui/ds.css` : the shared design system. Read all of it. Use its classes.
5. `ui/screens/dashboard.html` : the approved anchor page. Match its quality, density, and voice. Copy its `<aside class="sidebar">` and `<nav class="tabbar">` markup exactly for app pages, moving the `on` class to the right nav item.
6. `ui/icons.html` : inline SVG icons to copy.
7. The reference notes and images named in your task, under `references/`. Open the specific reference images with the Read tool and study them before designing.

## Hard rules
- **Do not edit** `ds.css`, `dashboard.html`, `icons.html`, `shoot.sh`, or any file another builder owns. Put page-specific CSS in a `<style>` block in your own page. If you believe a rule belongs in `ds.css`, say so in your report instead.
- Link the stylesheet as `<link rel="stylesheet" href="../ds.css">`. Save pages in `ui/screens/`.
- **Responsive is required.** Every page must look intentional at 1440px wide and at 393px wide. Use the `.g` 12-column grid and `span-*` classes; they already collapse. Add your own `@media (max-width:720px)` rules where needed. No horizontal scrolling at 393px.
- **AI marker discipline.** The gradient (`.ai-card`, `.ai-tag`) appears only on AI content. Every AI block shows: a plain sentence, the evidence or inputs it used, a freshness or "based on" line, and a short "Generated by AI" note. Anything AI drafts has Approve, Edit, and Regenerate. AI must be clearly prominent: the professor asked for heavy, visible use of AI.
- **Security is visible** where the blueprint says so: consent, encryption, approve-before-send.
- **Status colors always come with a word** (On plan, Below plan, Good).
- **Plain language.** Say "provider" not ISP, "response time" not latency, "fair line" not threshold. No jargon without a plain explanation. Short sentences. No lorem ipsum. No emoji.
- Light theme by default. Use `class="dark"` on a container only where your task says the moment is dark and immersive.
- Do not copy any other company's logo, brand name, or artwork into the designs. Borrow layout patterns only.
- Mark simulated content honestly: include a small "Sample data" note on pages showing results.

## Verify by looking (required)
From `ui/`, run `./shoot.sh <page-name>` for each page. It writes `shots/<name>-desktop.png` (1440 wide, full page), `shots/<name>-mobile.png` (393x852 first screen), and `shots/<name>-mobile-full.png` (393 wide, full page). Note: in the full-page mobile shot the fixed tab bar appears partway down the page; that is a capture artifact, ignore it.
Then **open every screenshot with the Read tool** and check: overlapping or clipped text, text wrapping badly, elements overflowing their cards or the viewport, uneven spacing, weak hierarchy, low contrast, empty dead areas, and anything that looks unfinished. Fix and re-shoot until both sizes look polished. Expect two or three rounds. If a full-page shot is very tall, crop it into pieces with Python PIL in your scratch space before reading so you can see detail.

## Report back (under 350 words)
- Files you created.
- For each page: one line on the layout and which reference patterns you used.
- What you checked in the screenshots and what you fixed.
- Anything still imperfect, stated plainly.
- Any rule you think should move into `ds.css`.
